# API consistency pre-review: HEC-RAS CRLF serialization

Date: 2026-10-01. Reviewer: independent api-consistency-auditor. Scope: read-only package writer inventory and proposed private shared helper. No Git mutations or engine execution.

## Verdict

PASS for implementation with the conditions below. A private `_ras_text.py` helper `_write_ras_text(path, text, *, encoding=None, errors=None)` is a minimal appropriate design. Accept str and pathlib.Path, convert using Path internally, preserve existing encoding/error arguments at each call site, and normalize CRLF and lone CR to LF before explicitly writing with `newline='\r\n'`. Do not add a terminal newline, remove blank lines, or strip content. Keep helper private so no public export/schema change is needed. Private helper functions are exempt from public @log_call rules; existing public static methods and logging decorators must remain unchanged.

The existing `RasPermutation._write_text_lines_crlf` (154-173) is a suitable *behavior reference*, but not a universal helper as written: it appends terminal CRLF to every list item and performs a verification read. Retain its existing list normalization/verification behavior as a thin wrapper around shared serialization, rather than using it directly for arbitrary text.

## Safety and compatibility conditions

1. RasPlan simulation date writer currently edits raw bytes to preserve unknown encoding. Normalize using a reversible byte encoding (latin-1 roundtrip) or shared bytes normalizer; do not replace it with UTF-8 decoding that could corrupt original non-UTF-8 content. Same principle applies to ScienceBase registered dependency byte repairs.
2. Atomic writers must retain permissions, same-directory temp creation, fsync, close-before-replace, and cleanup behavior. A helper accepting an existing stream, or a shared normalization helper used before stream.write, is appropriate where path-only helper would weaken safety.
3. RasBoundary exact deletion (`_build_plan`:1009; `_write_temp`:1235) uses original snapshot bytes, block hashes, and exclusive publication. Normalize predicted bytes in planning; expected retained block hashes must be hashes of normalized original block bytes. Keep original source/block selector hashes and source/prefix/suffix evidence unchanged. Result newline and temporary validation must expect CRLF. Keep exclusive descriptor writer and inode/hash/lock protections unchanged. Update deletion contract docs/tests to state content preservation apart from mandatory CRLF serialization. Never silently bypass its hash checks.
4. Explicit legacy native-Linux conversion utilities are a compatibility decision: `RasUtils.dos2unix` and `RasPreprocess._fix_x_file_line_endings` deliberately emit LF. Automatic dos2unix is invoked by RasCmdr native Linux/WSL lanes at 5932,6443,7154; `.x##` repair at RasPreprocess:592. Wine steady-flow evidence does not establish native Linux solver requirements. Parent should retain explicit opt-in utility behavior while preventing automatic preparation from undoing CRLF policy, and document any native Linux compatibility limitation rather than claiming native solver validation.

## Verification required

Assert CRLF bytes under platform-independent newline semantics; patching os.linesep alone is insufficient because TextIOWrapper uses its own platform behavior. Tests should inspect written bytes, ensure no bare LF/CR or CRCRLF, exercise UTF-8 and byte-preserved non-UTF-8 content, keep empty/missing-final-newline inputs stable, read LF and CRLF identically, and repeat writes idempotently. Use real small canary evidence as regression fixture. Add actual writer route coverage and safety regression coverage for atomic/boundary paths. Run targeted and full pytest and changed-file Ruff checks; report pre-existing baseline failures separately.
