## Proposed design audit

Perimeter agent proposed `HdfMesh.get_mesh_perimeter_faces(hdf_path: Union[str, Path], mesh_name: str) -> GeoDataFrame` with decorators `@staticmethod`, `@log_call`, `@standardize_input(file_type='geom_hdf')`. Proposed fields: mesh_name, face_id, cell0, cell1, interior_cell_id, exterior_cell_id, fp_start_index, fp_end_index, face_length, nullable bc_line_id/bc_line_name/bc_line_type, geometry. Native mesh-local face IDs are retained; all physical perimeter faces are selected from adjacency, independent of assigned boundary lines. Ghost/interior cell classification must be grounded in real native metadata. Association parsing must fail on missing/stale authoritative data where BC lines exist, duplicate ownership (including repeated rows owned by the same line), invalid endpoints and non-perimeter assignments. Null owner is reserved for verified unassigned faces. Geometry CRS, nullable integer/string types and deterministic empty schema need explicit docstrings/tests. Root owns schema registration in this clone. Existing decorator supports ras_object implicitly; explicit keyword parameter is preferable for machine-visible discoverability, but not a compatibility blocker under the existing HdfMesh pattern.

Replacement agent proposed `GeomBcLines.replace_bc_lines(geom_file: Union[str, Path], unsteady_files: List[Union[str, Path]], *, area_2d: str, lines: List[Dict[str, Any]]) -> pd.DataFrame`. Specs include name, coordinates and bc_type; Normal Depth requires friction_slope; Flow/Stage Hydrograph use existing hydrograph writers. Empty set clears named target-area lines while retaining area rainfall and unrelated blocks. Explicit clone paths avoid global project fallback. Required @staticmethod and @log_call apply. Existing standardize_input is specifically an HDF/global-number resolver and rewrites only its first HDF argument; applying it blindly to a multi-file geometry/unsteady transaction would misrepresent semantics. Explicit text-path normalization is an intentional existing-pattern exception, documented here, not a missing implementation requirement. New table schemas must be registered by root.

Transaction: stage all geometry and flow files on their respective volumes, validate all replacements and dangling-reference postconditions before mutation, create backups, commit by atomic per-file replace and rollback exact original bytes on exceptions. Preservation must include byte-exact unrelated native blocks and tails, all supplied unsteady files, rainfall/no-line target blocks, and clone-only writes. Reject duplicate names, malformed/unterminated native blocks, coordinate NaN/Inf, fixed-width name overflow and delimiter/newline injection before commit. No source-project mutation can be guaranteed from a direct path alone: contract requires caller-supplied clone paths and examples/tests must prove source hashes unchanged. Root must explicitly describe transaction boundary: exception rollback is multi-file failure atomicity, not process-crash atomic visibility across several files. A stronger crash guarantee would require a durable recovery protocol and cooperating readers.

## Design disposition and verification gates

Both additive designs satisfy static placement, names, logging, flexible path contracts, DataFrame conventions and backward compatibility subject to the gates above. No unresolved API-pattern blocker; informed producer agents of required fail-closed ownership, input validation and staged-transaction safeguards before implementation. Native adjacency qualification, rollback tests, schema registration and native compile/ownership evidence are implementation/postaudit gates, not facts already verified. Root accepted documented exception atomicity with no global crash/concurrency atomicity guarantee. Preserve all existing API signatures and SA/2D connection source untouched.
