## API consistency findings and resolutions

- `HdfMesh.get_mesh_perimeter_faces` uses the static namespace, `@log_call`, geom-HDF `@standardize_input`, flexible str/Path input, explicit keyword `ras_object`, and a GeoDataFrame. Native mesh-local IDs, adjacency, all physical perimeter faces, complete geometry, native length and nullable BC ownership are preserved. Physical cell count comes from native collection metadata; positive-area ghosts are not incorrectly classified as physical cells. Unknown mesh, partial topology, nonintegral/bounds-invalid IDs, duplicate owners, stale endpoints and non-perimeter attachments fail closed. Missing native association evidence where named-area lines exist raises rather than presenting false unassigned ownership.
- Existing `HdfMesh.get_mesh_cell_faces` now has `@log_call`; its historical signature and return/error behavior remain compatible.
- `GeomBcLines.replace_bc_lines` uses the static namespace, logging, flexible explicit text paths and a DataFrame result. It documents why the HDF-specific standardizer is unsuitable. Native-facing paths now use `RasUtils.safe_resolve`, preserving mapped drive letters. Optional project metadata checks completeness of associated unsteady files and rejects flow files shared with another geometry. No global project fallback is introduced.
- Complete target-area replacement preserves unrelated geometry, unrelated area/1D boundaries, rainfall and flow trailers. Existing forcing writers run on isolated staging flow files, preventing their scans from disturbing retained blocks. New target references and types are validated against the complete proposed set before publication. Duplicate identities, malformed blocks, name overflow/injection, nonfinite/degenerate coordinates and invalid forcing reject before writes.
- Same-directory atomic file swaps plus byte-exact exception rollback and retained backups implement the documented transaction. Postcommit metadata refresh failure now produces a warning and `attrs['boundaries_df_refreshed']=False`; it does not raise an exception claiming that already committed edits failed. The return doc describes this recovery evidence.
- Both new DataFrame column surfaces are registered in canonical `schemas.py`; schema version is 1.18. Column names and meanings match source and reference docs. Existing exports already expose both owning classes; no new module exports or SA/2D connection code changes are needed.
- API reference examples and release notes accurately describe native geometry BC type versus flow forcing type, deliberate unassigned faces, clone-only caller responsibility, complete associated-flow input requirements, native preprocessing and transaction limitations.

## Explicit limits and follow-ups

The caller must provide a disposable clone and, without ras_object metadata, every associated unsteady file. The API cannot identify an arbitrary direct path as an immutable source. Forcing is applied uniformly to all supplied flow files; supported types are Normal Depth, Flow Hydrograph and Stage Hydrograph. Exception rollback is not crash/concurrent-reader global atomicity; callers must exclude concurrent access, and a filesystem failure during rollback can prevent restoration. Compiled HDF remains unchanged until preprocessing. Topological hole-edge faces are inventoried, but hole-ring classification, boundary-constrained breaklines and broader multi-version native qualification are follow-ups. Root owns full-suite results, final lint/format checks, report/PR integration and the final commit; those results are not invented here.
