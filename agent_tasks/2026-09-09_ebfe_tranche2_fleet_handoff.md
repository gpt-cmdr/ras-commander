## 1. What this campaign is

FEMA publishes eBFE/BLE HEC-RAS studies decomposed: terrain, land cover, infiltration, soils
and DSS boundaries ship separately from the project, and references that survive point at
the authoring machine's tree. Nothing opens or runs as delivered. We hold the full corpus
(329 eBFE studies, 15.99 TB, at `F:\eBFE\raw\<key>\`; plus Alabama BLE, 26 groups, 83 GB, at
`F:\BLE_State\AL\raw\`) and are producing, per study, a **durable audit that is a replayable
repair recipe**: what a HEC-RAS engineer must do — recursive extraction, file movement, path
correction, reconstruction, acquisition — to get from the delivered zip to a running model.
Extraction is disposable; the audit is the product. Contract confirmed by the user: the audit
is executed against a fresh extraction of the raw archive, not a record of what one worker did.

Roles: **this session is the coordinator and does no auditing.** One subagent per Proxmox
container drives the work over SSH. Workers stream from the NAS to container-local scratch,
audit, write knowledge back to `F:\eBFE\audit\<key>\`, and discard the working copy.

## 3. Decisions already settled — do not reopen

D1 workers are Proxmox LXCs, one subagent each · D2 **no hashing of corpus data** (size vs
sidecar + ETag + zip CRC) · D5 uniform map styling across sources · D6 framing is "audit log /
data gap analysis", never "deficiency" · D8 blocked studies hatched, `blocked: true` · D10
generated knowledge never under `raw\` · D12 keep published result HDFs · D13 work unit = one
model (2D) / one group (1D) per worker · **D14 reassembly is descriptive, not mutative**:
delivered files are never rewritten in place; the audit records the recipe; *relocation* of
separately-delivered assets in the working copy is assembly and is allowed and recorded
(`asset_relocation`); rebuilt terrain is the one stored artifact (`audit\<key>\terrain\`).
Expected-ness of supporting elements is **derived from the model, never asserted** — optional
layers (infiltration, soils, land cover, DSS; terrain and projection for 1D) are expected only
when referenced. "Runnable as delivered" means **zero actions**. **Critical = any acquisition gap** (verdict *needs data not in the delivery*); the map hatches that
set and lists each gap in the sidebar.
  Per unit at `1a5e3b4b6` (six studies / eight work units carry the row): `12030102` DSS,
  infiltration · `12070205` terrain (5 projects, modifications referenced), DSS, infiltration,
  soils · `12100201` DSS, infiltration, soils · `12100302` terrain (1 project), DSS, infiltration,
  projection, soils · `13070007` infiltration, land cover, soils · `12070104` MA01/MA03
  infiltration, land cover, soils, MA02 adds DSS. No row on `12040102`, `12040203`, `12090301`,
  `12110205`. **A missing `Terrain.hdf` is
critical, not merely reconstructible**: terrain modifications (channel cuts, levees, polygon
overrides) live inside that file, and no model here was plausibly built without one — so
rebuilding from delivered rasters is a `reconstruction` that runs but is not faithful, *and* the
modified terrain is a blocking `acquisition`. Captured as `terrain.modifications` (every
modification element under each `.rasmap` terrain layer, plus `/Modifications/` from any
delivered HDF) and `critical_missing[]`; the map shows such studies with their own hatch.

Three durable operational rules, each earned by an incident:
1. **A durable record is never removed before its replacement is fully written** — regenerate
   to temp, verify, atomic rename. (An empty deploy once deleted all ten audit directories.)
2. **A changed deploy is verified before it is trusted** — size > 0, a known symbol, and one
   real study end-to-end before a batch. (`base64 -d` on empty stdin wrote a 0-byte worker that
   `py_compile` accepted.)
3. **Every reported deficiency is reviewed by a different code path than the scanner that
   produced it** — archive-member basename match via the library reader, cross-detector
   consistency, proximity disambiguation, same-path duplicate rule (path + declared size +
   CRC from the central directory). Only `review.verdict == real` counts.
