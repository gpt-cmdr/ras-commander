# Native unsteady container release — 11 September 2026

The HEC-RAS 6.5 and 6.6 native Linux images are published and ready to run
the qualified 2D workflow. Each contains the official matching Linux solver,
its vendor libraries, and [ras-commander][source]. Use the matching published
Wine preprocessing image first, then call the native image through
[RasDocker.compute_plan()][api].

## Published images and source

Both repositories are public. The `v1` and `latest` tags identify the same
tested image in each repository. These are `linux/amd64` images.

| 6.6 | [rascommander/hec-ras-linux-unsteady_6.6:v1](https://hub.docker.com/r/rascommander/hec-ras-linux-unsteady_6.6) | `sha256:1a11348bd6a96a580959b846133214f4b058ece6c8b4382b7210e3a74fc80066` |

The installed source and OCI revision label are
[`e5380db6d37e2c62c763bf6221c3ab3219fddf80`][source]. The package distribution
still reports `0.99.2`; the source commit identifies this container API build.
The host installation command in the [operating guide][guide] selects that
commit explicitly. Documentation and notebook updates in the PR follow the
image's code commit.

Pull either pair of matching images, for example:

```bash
docker pull rascommander/hec-ras-wine-precompute_6.5:v4
docker pull rascommander/hec-ras-linux-unsteady_6.5:v1
```

For 6.6, change both version suffixes to `6.6`. The [example notebook][notebook]
calls both stages through Python and uses `pull="always"` by default.

## What was executed

The model came from the public [ras2fim sample data][sample], under
`sample_output/02_model_copies/`:

```text
1919912_wb-2427466_wb-2427467_14-hr_50-cfs_to_11609-cfs
```

Each version used a fresh working model with its original geometry HDF and
the complete `source_terrain` and `projection` siblings. The project was
mounted at `/job`; dependencies were mounted read-only at `/source_terrain`
and `/projection`. Preprocessing used the matching published `v4` Wine image.

| Host and run | 6.5 | 6.6 |
|---|---|---|
| Linux, complete 266-hour plan, four solver cores | Passed; final HDF 7,400,731 bytes | Passed; final HDF 7,409,346 bytes |
| Windows Docker Desktop, every notebook code cell, one-hour demo, two solver cores | Passed; final HDF 3,052,376 bytes | Passed; final HDF 3,060,415 bytes |
| Prepared temporary HDF retained after native compute | Passed | Passed |

The complete Linux runs cover **1 January 2000 00:00 through 12 January
2000 02:00**, with **267 output times and 6,548 water-surface columns**.
Every water-surface value was finite. The HDF file-version attributes report
HEC-RAS 6.5 February 2024 and HEC-RAS 6.6 September 2024 respectively.

The sample's collection metadata reports **6,201 cells**, while its coordinate
array and water-surface arrays contain **6,548 columns**. The notebook displays
and checks both quantities separately. Its inspection and plotting cells were
also run against both complete Linux outputs.

Windows testing used Docker Desktop's WSL2 Linux engine, Docker Server
29.7.2, and Python 3.14 on the host. Both complete notebook executions used a
Windows host directory containing spaces. The one-hour demo explicitly
shortened only each working copy before preprocessing and produced two output
times spanning that hour. Windows qualification does not represent a full
266-hour Windows-host run. Image layers, configuration and source labels were
checked against the Linux builds before notebook execution.

## Failure and recovery checks

Real container runs verified the following behavior:

- A preparation/native version mismatch fails before launching the solver.
- A missing or changed compiled input fails before launching the solver.
- An existing final HDF remains intact without explicit replacement.
- A one-second solver timeout fails without publishing a final result.
- An owned container killed while its solver was running exits with code
  137, releases its file lock, and preserves the host's prepared input.
- A fresh run ID successfully completes the full 6.5 plan after that kill.

The input-validation failures were also tested with replacement enabled and
an existing final HDF: the original final file stayed intact. Prepared source
fixtures remained unchanged. No test containers remained running afterward.

Focused host API, native worker, runtime bundler, native executable-path,
and existing Linux regression tests reported **109 passed, 2 skipped**.
Notebook conversion and documentation generators passed. The strict MkDocs
build still reports **34 pre-existing warnings**, with zero warnings from
the new guide or notebook.

and result inspection; it does not establish hydraulic calibration.
