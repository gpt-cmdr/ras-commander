# HEC references for capability planning

Use these references before choosing boundary types, meteorological inputs, mapping semantics, or land-surface methods. HEC manuals describe HEC-RAS behavior and methods; installed RAS Commander, fast-dss, fast-map, and ras2cng contracts establish which operations the current environment exposes. A manual link does not establish API support or qualify a project.

## Choose the applicable version

Record the engine version, solver, model dimensions, task, and relevant package versions in the plan. Start at the [HEC-RAS documentation portal](https://www.hec.usace.army.mil/confluence/rasdocs) and select the engine's manual version. The links below were opened and checked on **November 17, 2026**. RAS links use the explicit **6.6** manual baseline, not a moving `latest` URL; use the matching version for a 7.x or older project and record any changed method or control. A page can retain historical version wording within its body, so inspect both its version selector and the relevant section.

These are passive, reader-activated citations. Do not add automatic fetching, embeds, mirrored manuals, or citation-driven network calls to modeling workflows. During planning research, open only the relevant official sections; report unavailable evidence instead of inventing a replacement URL.

The guide demonstrates MRMS conversion and DSSVue inspection. These pages are not pinned to a Vortex release; check the installed tool. HMS-specific grid requirements are not automatically RAS requirements, and Vortex coverage is not proof of native fast-dss coverage. |
| DSS exchange: what do pathnames and time bounds mean? | [General concepts for HEC-DSS, DSSVue User's Manual](https://www.hec.usace.army.mil/confluence/dssdocs/dssvueum/introduction/general-concepts-for-hec-dss) | Distinguish regular/irregular time-series, paired, and grid conventions. Grid records use start/end times rather than the regular-series interval convention; inspect header units/data type and UTC grid bounds. A valid catalog alone does not establish complete forcing coverage. This web manual is not a fast-dss API contract. |
| Mapping: which quantity, saved profile, terrain, and output mode are being compared? | [Creating results maps, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/mapping-results/creating-results-maps) | Select quantity/profile/output mode and associated terrain. | Land use and roughness: how do classifications become model parameters? | [Land classification layers, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/land-classification-layers) | Check classification IDs/names, source priority, raster resolution, classification polygons, parameter tables, and geometry association. Land-cover categories are a surrogate for roughness, not calibrated channel roughness. Retain the class-to-parameter lookup and verify final preprocessed values. |
| Soils and infiltration: which method and initial estimates are justified? | [Infiltration methods, 2D User's Manual 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/r2dum/6.6/developing-a-terrain-model-and-geospatial-layers/infiltration-methods); [Land classification layers, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/land-classification-layers) | Choose SCS Curve Number, Deficit Constant, or Green and Ampt based on the intended application and available inputs. | Infiltration overrides: what actually reaches each cell? | [Infiltration parameters, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/geometry-data/infiltration-parameters) | Distinguish the base layer, geometry-wide overrides, regional overrides, and final-value raster. Plan separate readback and preprocessed-cell checks rather than assuming a changed source table changed the active geometry. |
| ras2cng delivery: what hydraulic meaning must an exported asset preserve? | [Mapping results, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/mapping-results); [Creating results maps, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/mapping-results/creating-results-maps) | Preserve plan/profile, quantity, terrain, units, CRS, and map semantics. Use ras2cng's own installed contracts for packaging and serving; HEC does not document or certify that project's export formats. |

## Terrain, HMS handoff, and consequence planning

These official sections were opened on November 17, 2026. Use current package contracts for the implementation; the HEC sources establish modeling concepts and checks rather than support for third-party engines.

| Workflow and planning question | Official reference and version | Decision informed and applicability check |
|---|---|---|
| Terrain acquisition and association: which surface drives geometry and mapping? | [Terrain layer, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/terrain-layer) | Record bathymetric coverage, terrain sources/priority, rounding, vertical conversion, stitching, CRS, and geometry/plan associations. Terrain resolution and computational mesh resolution are separate choices; a displayable VRT alone does not establish the terrain used by preprocessing. |
| Terrain modifications: what is the effective surface and what must travel with a clone? | [Terrain modification, RAS Mapper 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rmum/6.6/terrain-modification) | Choose replacement, high-ground/channel, or additive modification behavior deliberately; retain source terrain and modification definitions. Virtual clones reference the base terrain, so their dependencies must remain available. Compare effective elevations and downstream preprocessing/mapping, not only the vector edit. |
| HMS-to-RAS handoff: where should the hydrograph enter the hydraulic model? | [Internal boundary conditions: Use with HEC-HMS Results, 2D User's Manual 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/r2dum/6.6/boundary-and-initial-conditions-for-2d-flow-areas/internal-boundary-conditions) | Identify the HMS subbasin outlet and whether upstream routing is already represented. Avoid distributing an already-routed outlet hydrograph along a long reach or area, which can route it twice. Check inflow location, incremental versus total contributions, units, time coverage, and the RAS boundary's cell allocation. |
| Consequences: which hydraulic outputs and exposure assumptions support an event estimate? | [HEC-FIA overview](https://www.hec.usace.army.mil/software/hec-fia/); [HEC-FIA features](https://www.hec.usace.army.mil/software/hec-fia/features.aspx) | The official overview identifies depth/arrival grids and DSS stage hydrographs as hydraulic event inputs; the features page distinguishes event consequences, inventories, loss functions, and uncertainty. Verify event/scenario, elevation/depth datum, inventory provenance, valuation basis, and function applicability. These web pages are not version-pinned technical contracts. They describe HEC-FIA, not go-consequences: no feature parity, interchangeability, regulatory acceptance, or HEC endorsement of go-consequences is implied. Use the installed go-consequences contracts and qualified examples for its actual supported methods. |

## Flood-science research planning

The following sections were also opened on November 17, 2026. Use them to design experiments and evidence collection before scheduling an ensemble. They do not supply universal acceptance thresholds or establish that a particular workflow is implemented in RAS Commander.

| Research question | Official reference and version | Planning decision and applicability |
|---|---|---|
| Are results sensitive to mesh and computational timestep? | [Selecting an appropriate grid size and time step, 2D User's Manual 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/r2dum/6.6/running-a-model-with-2d-flow-areas/selecting-an-appropriate-grid-size-and-time-step); [6.6 solver changes](https://www.hec.usace.army.mil/confluence/rasdocs/rasrn/6.6/new-features) | Plan mesh/time refinement together, preserve key flow barriers, and compare decision-relevant output quantities. Identify the selected equation set and actual timestep history. Read the release-specific solver changes before applying Courant guidance: the 6.6 manual retains explicit SWE-EM wording, while its release notes describe a semi-implicit advection change. Record this discrepancy; do not turn either passage into a universal stability limit. |
| Which changes measure numerical sensitivity versus physical uncertainty? | [Model accuracy, stability, and sensitivity, User's Manual 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rasum/6.6/performing-a-1d-unsteady-flow-analysis/model-accuracy-stability-and-sensitivity) | Separate experiments changing timestep, spacing, or numerical settings from those changing roughness, boundary inputs, or physical parameters. Retain baseline, run messages, conservation diagnostics, and comparable output metrics. This section addresses 1D unsteady analysis; its cross-section and theta guidance does not automatically apply to a 2D solver. |
| What observations and events support calibration and independent evaluation? | [Calibration of unsteady flow models, User's Manual 6.6](https://www.hec.usace.army.mil/confluence/rasdocs/rasum/6.6/performing-a-1d-unsteady-flow-analysis/calibration-of-unsteady-flow-models) | Examine observation datum, time basis, rating-curve limitations, high-water-mark quality, and geometry before fitting parameters. Use physically defensible parameter ranges and reserve other events or periods for evaluation. HEC calls this latter step verification; retain that source terminology while defining the study's validation/evaluation terms. If evaluation prompts retuning, disclose it and rerun the affected comparisons. The manual's 1D examples are not a universal 2D calibration protocol. |
| What does an uncertainty ensemble represent? | [Uncertainty analyses, HEC-HMS User's Manual 4.14](https://www.hec.usace.army.mil/confluence/hmsdocs/hmsum/4.14/assessing-model-uncertainty/uncertainty-analyses) | For HMS-to-RAS research, distinguish sampled hydrologic parameters from uncertain meteorology, boundaries, terrain, and hydraulic structure. Record distributions, dependencies, sampling policy, and omitted uncertainty sources. This chapter describes HMS parameter uncertainty and identifies separate integrated assessment needs for meteorology; it is not evidence of a native RAS uncertainty-trial API. A sensitivity range alone is not a probabilistic confidence interval. |

For a flood-science study, define the hypothesis, comparison quantities, observational support, calibration/evaluation split, numerical sensitivity design, and uncertainty assumptions before execution. Record failed or excluded runs and their reasons; execution success, input readback, and mapping parity establish different things from agreement with observations. The repository notebooks below demonstrate mechanisms and particular qualification checks, not general validation of a flood model or universal research conclusions.

## Connect the manual to executable examples

Use the repository's domain-skill references for current API calls. These examples show where the planning decisions become observable checks; read notebook source cells and retained evidence rather than rerunning them just to look up a workflow.

- [211: final Manning's n and infiltration](https://github.com/gpt-cmdr/ras-commander/blob/main/examples/211_final_mannings_and_infiltration.ipynb) anchors final-value inspection.
